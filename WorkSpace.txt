1. Logika Keuangan & Transaksi Tersebar (Bypass Service Layer)
 * Masalah: Pada memberRepository.js, fungsi payDebt() mencatat transaksi pembayaran utang (debt_payments.add) sekaligus mengubah saldo utang member. Namun, pembuatan mutasi akun kas (cash_mutations) untuk uang masuk dari cicilan tersebut justru diabaikan di fungsi ini.
 * Dampak: Saldo kas tidak otomatis bertambah saat member mencicil utang, kecuali jika tombol "Hitung Ulang" di halaman Keuangan dipanggil secara manual.
 * Rekomendasi: Pindahkan logika pembayaran utang dari repository ke financeService atau memberService yang mengelola perubahan utang member sekaligus pemutakhiran mutasi kas secara atomic.


 
2. Percampuran Tipe Transaksi pada Repository
 * Masalah: transactionRepository.getWithDetails() menggabungkan data transaksi barang dari IndexedDB (transactions) dengan data dari digital_transactions lalu memformat ulang struktur datanya.
 * Dampak: Repositori yang seharusnya hanya menangani kueri tabel transactions mengambil alih business logic pemformatan data dan perhitungannya (misal perhitungan kasImpact).
 * Rekomendasi: Pindahkan fungsi penggabungan dan transformasi data ini ke salesHistoryService atau reportsService.


 
3. Komponen UI Mengakses Database / Repository Secara Langsung
 * Masalah:
   * Reports.vue memanggil db.transactions.toArray(), db.digital_transactions.toArray(), dan db.products.toArray() secara langsung di dalam komponen UI.
   * Settings.vue mengakses objek db.tables secara langsung untuk mengekspor data backup.
   * Categories.vue memanggil unitRepo secara langsung alih-alih melalui composable/service.
 * Dampak: Komponen UI terikat erat (tightly coupled) dengan implementasi database. Jika library/skema database berubah, berkas komponen UI juga harus ikut diubah.
 * Rekomendasi: Bungkus kueri data laporan dan ekspor/impor backup di dalam service layer (reportService dan backupService).


 
4. Redundansi Pemanggilan Sinkronisasi Cloud
 * Masalah: Pemanggilan syncRealtime.pushLocalToCloud() dilakukan secara manual dan berulang di dalam composables (useCategories, useMembers, useOperators) serta di dalam service (shoppingService).
 * Dampak: Menyulitkan pemeliharaan kode (maintenance) karena jika metode sync berubah, pemanggilan harus diubah satu per satu di banyak tempat.
 * Rekomendasi: Manfaatkan Dexie Hooks (db.table.hook('creating'), 'updating', 'deleting') untuk memicu push sinkronisasi secara otomatis saat terjadi perubahan data lokal.
